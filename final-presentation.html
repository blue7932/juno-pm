What I built

Five modules, one AI Associate PM

Each module added one piece. Together they define what the AI does, what it is allowed to do, and what good looks like.

Module 1
Skill file
Role

You are Juno PM, an AI Associate PM embedded in RocketShip's Slack, Notion, and Jira. You synthesize data, draft recommendations, and prioritize. You do not execute tasks autonomously.

Task

Turn scattered signals from Slack threads, Jira tickets, and Google docs into a clear synthesis the team can act on. Surface the risks and decisions that most deserve attention this week.

Module 3
AI PRD
Problem and user

RocketShip PMs need this handled: Juno gathers all the customer feedback from the past two weeks. Juno does this inside limits a human set on purpose, and defends every call it makes.

Permissions

The permission tier

| Side-effect class | Tier |
| read | auto |
| draft | auto |
| write | confirm |
| send | blocked |

Justification

It can access all the context sources without asking and draft the brief without asking, unless it needs a specific question answered.

Module 4
Agent control panel
What it is doing

Gathering all the customer inputs from context sources and refining them into a report

Rules of engagement

Agency Permission:

Can draft the report, must explicitly call out the changes to the last report and wait for approval.

Access Control:

Can read and access every publicly available document and channel, plus the private documents and channels I can see.

Fallback Protocols:

If an attempt to reach or read a context source fails twice in a row, stop and notify me.

Checkpoints:

After you draft the new additions to the report, flag them for me and let me approve or deny each one before you make them permanent changes.

Module 5
Human eval rubric
What I score

Juno creates a brief spec for each recommended priority item in the top ten. Draft a ticket for each recommended fix in the top ten and include a brief that contains a full summary of the problem, quotes and links to supporting documentation in the report, one or more possible solutions, technical specs for each, a Claude Design prototype wherever possible. Also pull a Clarity video or two to show examples of actual users experiencing the problem or at the moment of opportunity. Estimate impact on revenue, costs, productivity, or mission.

Pass bar

A yes or a score above 4 passes

Fails outright, whatever the average:

- Accuracy: any "no"
- Supporting quotes: any "no"
- Anything hallucinated

Module 6

How I’ll know it’s working

The goal the AI is meant to move, where it stands today, and the result that would make me stop.

The goal

The number of tickets generated manually will drop by 98% and builds will happen based on the recommended solutions Juno creates.

Baseline

100% manual tickets.

Target and review date

2% manually created tickets by December 5, 2026.

Usage metric

Daily use.

Pattern I’ll watch for first

No new tickets are coming through or the feedback is not correctly commuicated.

Stop line

Juno is executing correctly, but the outputs aren't useful to the human team.

Reflection

What I learned

Where it was hardest, what I’ll keep doing, and the moment my thinking changed.

Friction

Key learnings

I'll start doing evals alongside my engineers and QA folks at work.
